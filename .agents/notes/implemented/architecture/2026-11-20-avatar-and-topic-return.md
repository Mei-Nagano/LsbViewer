# Agent Note: 头像更新与帖子返回保留

Status: implemented

## Problem

用户反馈别人头像更新迟缓、从主页等页面返回帖子会重载、节点中心入口不明显。源码显示头像内存和磁盘字节没有有效期，且网络优先删除 URL 查询参数；解码缓存也仅以 URL 为键。帖子分页数据已在返回栈 ViewModel 中，但 UI 几何状态会丢失、WebView 在离开组合时被销毁。节点入口只有板块导航右上角。

## Decision

头像保留源站完整版本参数，缓存一分钟后重新获取，过期缓存仅用于请求期间的显示，刷新失败保留已展示图片；解码缓存跟随内容变化。图片请求携带重新验证缓存的要求。

将帖子 UI 状态、列表位置和正文 WebView 绑定到同一个帖子返回栈条目。临时离开时暂停并释放页面回调，返回时重新绑定而不重新加载正文；条目真正出栈时销毁 WebView。通过可更换的 Context 避免保留旧 Activity。路由显式传递自己的条目。

头像信息卡新增阅读与交互设置，默认保留当前信息卡行为；关闭后点击头像直接进入该用户主页。用户 ID 已知时不请求摘要，只有用户名时使用现有按用户名进入主页的路由；开关纳入持久化、会话同步、重置及备份。

节点已有独立底栏入口后，按用户要求移除首页标题栏下和侧栏重复的节点中心入口，保留节点底栏和板块页入口；与[节点适配决策](../../implemented/architecture/2026-11-20-source-nodes.md)保持一致。

## Alternatives considered

每次都禁用头像缓存最容易确保新图片，但会造成列表请求量和闪烁；使用短有效期且保留旧图展示。删掉版本参数可绕过历史带参请求的网关故障，但会失去源站更新标识；优先原 URL，仅在失败后保留原有去参恢复路径。

只缓存帖子 HTML 占用较少，但返回仍须重建 DOM、资源和布局，不满足原位返回体验；保留当前返回栈中的实例，出栈即释放。

把所有头像永久改成直达主页可减少一次点击，但用户明确要求可关闭信息卡，因此保留两种方式并提供持久开关。

## Consequences

头像更新会在下次进入相关展示且缓存到期时获取，固定 URL 最多短暂保留一分钟缓存；保留帖子会增加在栈页面的内存占用，显式刷新、主题变化或页面内容变更仍正常更新。只进行源码检查、静态检查和排除测试的编译；不开展测试或设备验证。
