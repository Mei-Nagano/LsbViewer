# Agent Note: 显示源站 PoW 原组件

Status: implemented

独立表单的抽取方式和未接管请求的拒绝策略由[原页面初始化上下文](../../implemented/bug-fix/2026-11-21-pow-page-context.md)部分取代；源站原组件、用户点击和成对结果提交继续保留。

## Problem

用户要求 PoW 原样显示并由用户点击验证。上一轮的原生计算按钮不符合这一交互要求。[旧决策](../../implemented/architecture/2026-11-20-web-resources-and-human-verification.md)中的资源网络修复保留，仅取代其原生 PoW 决策。

## Decision

保留源站组件 HTML、页面声明的样式与脚本，在独立 WebView 表单内展示，使用源站脚本处理用户点击、计算、刷新和状态。应用只观察完成状态，成对读取当轮 challenge/proof 后交给原有提交链路，不自动点击、不计算 PoW。登录、回复、通用表单共用组件。

组件资源和刷新 GET 通过已有共享客户端，延续 Cookie、DoH、代理和 HTTP/3 回退；只允许可信源站资源与人机验证刷新地址。表单解析保留源文档资源引用。

用户再次反馈组件无法加载。源码显示外部脚本全部前移到 head，非延迟脚本可能在原表单建立前执行；ready 又额外依赖 humanVerificationPowReset 全局函数，超出实际使用的 bbsHumanVerification.ready/append/reset 接口。组件请求的访问验证响应没有进入恢复流程，所有非白名单资源直接返回 403，任意子资源错误都会让整个组件失败。本轮修复将样式保留在 head，初始化配置与外部脚本按源文档顺序放到原表单之后；使用实际所需 API 判断 ready，组件始终可见。Cloudflare 访问验证通过现有用户交互流程恢复后重新加载，一次自动恢复后仍失败则交给用户重试，避免反复弹窗。恢复入口在 IO 调度器执行现有访问验证协调器，避免旧 UAM 同步联网路径在主线程运行；用户验证对话框由会话层切回主线程。数据资源交还 WebView，非核心图片字体失败不判定整个验证失效；源站脚本、样式、刷新请求仍报告具体错误。

## Alternatives considered

原生按钮省去脚本下载且能取消后台计算，但无法满足用户要求的源站原样交互，并需要维护站点算法，因此移除。

完整源站登录页能保留所有上下文，但会替换现有账号输入、密码保存和回复流程；选择嵌入原验证组件。

## Consequences

界面与验证流程由源站维护；新增源站脚本和样式依赖，需要展示加载失败并支持重新加载。原 form 的属性保留，应用使用独立 data 标记定位；脚本初始化与组件加载状态互相独立，不再以 15 秒计时中止正在等待用户的访问验证。网络准备失败直接提示，关闭组件时取消等待加载的协程；会话层在 finally 中移除属于当前请求的验证对话框，取消恢复请求不会遗留全局弹窗。挑战刷新后必须同步提交新 challenge 与 proof，重置、过期、卸载时清空可提交结果。只做源码检查、静态检查和排除测试的编译，不进行测试或设备运行验证。
