# Agent Note: 源站节点的原生浏览入口

Status: implemented

入口展示与[头像更新与帖子返回保留](2026-11-20-avatar-and-topic-return.md)一致：节点底栏、我的页面和板块导航提供入口；按用户要求，首页标题栏下和首页侧栏不再重复展示节点中心。

## Problem

源站 /nodes 和 /node/{id} 提供节点目录、主题及排序，但应用仅映射旧板块路由。帖子所带节点链接落入通用网页，没有可发现的节点中心入口。

同主题审计：现有网络与人机验证笔记处理另一问题，没有需取代的节点记录。

用户进一步确认淘贴中心已经全面由节点替代。底栏、我的页面、布局设置和帖子菜单仍提供旧淘贴入口；本次补齐入口替换及旧导航偏好的迁移，保留用户已有顺序，旧专辑编号不能假定等同于节点编号。

## Decision

新增节点页面模型、解析与原生列表，按源站 .node-tabs 的 URL/选中态切换我的、管理、热门、推荐、最新、主题及详情排序，分页保留当前查询参数。节点详情复用帖子卡片；帖子标题处展示源站节点归属并路由到节点详情。板块导航增加节点中心入口。

节点搜索、创建、管理及依赖页面脚本的编辑操作继续使用显式的应用内源站入口，保留页面权限、图标裁剪、批量选择和验证协议。未登录的列表显示源站提示及原生登录入口，登录返回后重新加载。节点搜索必须保留 scope=node，不落入默认的全站主题搜索。

节点全面替代淘贴：底栏默认目的地、布局选项和我的页面改为节点，帖子菜单改为管理帖子节点。底栏稳定 ID 迁移到 nodes，导航偏好版本升级到 4，旧别名与备份恢复映射到新 ID，保持原有顺序并去重。根页面使用 nodesRoot，节点详情仍使用带 URL 的 nodes 路由。旧淘贴中心链接转到对应节点目录，旧专辑详情编号不转换成节点编号；旧专辑操作路由仅兼容导航，不再发起淘贴操作。

## Alternatives considered

全部使用网页可直接保留完整操作，但不能给应用提供原生目录、排序和帖子节点导航，因此只保留需要完整脚本的操作入口。

把节点当作旧板块复用现有模型最省代码，但它们的 URL、权限、排序和归属是独立协议，会误把节点编号当版块编号；采用专门的节点模型，帖子卡片继续复用。

继续并列展示淘贴和节点能保留旧客户端入口，但源站已全面替代淘贴，会把用户引向失效操作，因此将入口和偏好一并迁移。

## Consequences

节点目录与帖子页不再混淆节点编号、板块编号和帖子编号。节点详情复用既有帖子卡片与屏蔽规则；分页保留当前标签、排序和其他查询参数。登录返回后通过账号身份版本刷新。

搜索、创建、关注、管理及图标编辑保留完整源站页面，避免静态原生表单遗漏脚本控制的字段和权限。代价是这些操作的界面继续由源站提供；需要独立原生化时应先取得相应登录态表单及请求证据。正文节点标签提取到标题下方，避免重复显示，登录用户获得管理帖子节点入口。底栏的节点入口替换原位置，保留用户选择和排序；兼容旧链接需要少量路由别名，但不推测旧专辑与节点编号的对应关系。
