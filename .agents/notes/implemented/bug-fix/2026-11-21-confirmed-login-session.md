# Agent Note: 登录结果与账号身份同步

Status: implemented

## Problem

用户反馈启用代理登录，帖子可以正常访问，但登录后应用始终显示未登录。源码中，原生登录只用重定向 URL 宣告成功，然后触发异步会话刷新；SessionRecovery 又以固定名称 bbs_auth Cookie 缺失直接写入访客身份、不请求源站。账号侧栏只取第一张 user-card，没有要求用户名链接指向有效用户。通用应用内网页在完成登录后也没有统一回传 Cookie 和刷新原生身份。帖子读取和登录提交共用 LsbClient.http 的动态代理选择器，WebView 加载前等待同一份代理发现结果；没有发现登录提交单独绕过代理的分支。没有设备复现，也未确认当前源站是否更改认证 Cookie 名称；这些是源码中可直接确认的判定缺口，不等于已经证实用户设备上的唯一根因。

## Decision

原生登录用共享身份解析器确认响应中的真实账号；无法确认时只补取一次首页，不重复提交登录。认证客户端返回 SessionSnapshot，账号服务在返回成功之前同步应用快照，推进恢复代次并取消旧请求。刷新和恢复以源站的明确账号/访客响应为依据，不用固定 Cookie 名称代替认证结论。侧栏选择包含有效 /user/数字 链接的用户卡，避免访客名字或第一张无关卡被认作身份。应用内网页在可信 HTTPS 源站页面完成时回传 Cookie，离开源站网页后刷新原生会话。保留错误页、验证页不清空既有身份，以及用户自己进行人机验证的机制。

## Alternatives considered

保留异步刷新，仅扩大 Cookie 名称识别，改动最少、无需返回账号快照。但没有当前源站协议证据支持另一固定名称，也不能消除返回首页时身份尚未确认的间隙，所以不选。

登录提交后直接把输入用户名写入已登录状态，界面响应最快，但输入可能是邮箱，而且无法确认用户 ID 或服务端是否真的认证成功，所以不选。

## Consequences

原生登录成功回调前同步真实账号快照；恢复代次推进会取消旧恢复任务并拒绝旧首页身份观测。刷新不再假定认证 Cookie 的名称，访客身份只来自源站明确的登录入口/表单。应用内源站网页在完成导航时回传 Cookie，退出网页时刷新原生身份。保留既有短重试、错误页不抹去身份、CSRF 与账号缓存联动和手动人机验证。

未知登录响应需要额外一次首页读取；网络失败明确提示无法确认账号，不重复提交登录表单，不写入猜测用户名或用户 ID。访客的显式会话刷新也读取一次首页，因此不再依赖本地 Cookie 快捷判定。帖子可以访问仅支持内容请求通畅，不能证明账号已认证；仍需源站返回的账号身份。代理路由保持现有共享网络策略，用户手机代理出口和登录结果尚未观察。
