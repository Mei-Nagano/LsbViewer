# Agent Note: PoW 保留原页面初始化上下文

Status: implemented

## Problem

用户在上一版安装包后再次反馈人机验证不能加载。源码中的组件抽取只保留 head 内联脚本和 /app/ 外部资源，丢掉 body 内联初始化、其他声明的脚本和组件祖先 DOM；验证码刷新以外的请求被直接返回 403，非 GET 也被阻断。原表单上的 bbsHumanVerification API 不能证明被抽取的页面能完成源站初始化。当前内置浏览器不可用，不能将这几处源码遗漏断言为手机实际失败的唯一原因。

同主题审计：[原组件](../../implemented/architecture/2026-11-20-original-pow-component.md)部分重叠，保留用户点击和结果桥接，取代独立表单重建；[资源网络](../../implemented/architecture/2026-11-20-web-resources-and-human-verification.md)部分重叠，保留 /app/ GET 的共享客户端；[访问验证](../../implemented/architecture/2026-11-20-doh-cloudflare-navigation.md)部分重叠，保留完整浏览器导航和 DoH 策略。其余节点、头像、奖励笔记无关。

## Decision

保留实际返回的完整源站文档及原脚本顺序，在其中标记目标组件、原表单和祖先节点。仅用样式隐藏非组件界面，保留 DOM 供原脚本初始化。模板表单在源码中有脱离原文档的调用，复制该表单组件到原文档内而不是丢掉资源上下文。源站 PoW 标记即足以识别协议，challenge 可以由原脚本加载，不因初始字段空缺拒绝有效组件。

应用的观察脚本在源站脚本之前安装，等待目标表单进入 DOM，只观察成对 challenge/proof，不代替用户点击、计算或提交。捕获原脚本加载和运行错误用于初始化失败提示。拦截所有页面表单提交以保留原生账号、回复和账号操作链路。

源站 /app/ 和刷新 GET 继续共享 Cookie、DoH、代理和 HTTP/3 客户端；其余资源、跨域验证依赖与非 GET 交还已经配置网络策略的 WebView，停止伪造 403。Cloudflare 恢复、重载和销毁流程保留。

## Alternatives considered

只补 body 内联脚本最小且不增加保留页面体积，但仍遗漏脚本依赖的 DOM 和非 /app/ 资源，前两轮的局部修复已经无法说明实际初始化条件，因此选择完整上下文。

用完整源站登录页替代原生登录能完全跟随站点行为，但会改变凭据保存、回复和账号操作流程。保留源文档上下文并只展示组件，提交仍由现有原生页面处理。

## Consequences

保留完整文档增加验证码模型大小并执行源站原初始化逻辑。页面外围只隐藏，不删除；应用阻止导航与页面表单提交，凭据、回复和账号操作仍由原生页面处理。组件祖先的隐藏布局、透明度和可见性被覆盖，避免原站折叠表单或弹窗使验证区域透明。CSRF 在源脚本执行前写回目标表单，含登录令牌补取的情况。

源文档和 body 初始化脚本不再被抽取规则删掉；模板组件不处于浏览器可查询的 template 内容中时才原位展示，脱离文档的组件保留源上下文。保留源站 /app/ GET 的共享客户端与访问验证恢复；其余请求由已应用 DoH/代理策略的 WebView 加载，第三方验证 Cookie 与 CAP 组件保持一致。应用不点击、不计算 PoW，不代替用户提交源站表单。
