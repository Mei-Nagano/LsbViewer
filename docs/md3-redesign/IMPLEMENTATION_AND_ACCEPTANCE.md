版本：2.0；日期：2026-10-21。状态：**开发设计，尚未实施；本文全部任务与验收项初态为待执行。**

## 1. 实施范围与不可变边界

本轮可调整默认配色、排版、层级、组件、页面布局、操作位置及响应式表现。
默认根导航调整为“社区、淘帖、消息、我的”；发帖成为上下文 FAB；消息组织私信与通知两个分区。
原有功能、权限、源站契约与持久数据保留；签到继续自动运行，不新增手动入口。

| 可以由 UI 更新改变 | 必须保持的契约 |
| --- | --- |
| 页面标题与根导航显示名称 | 旧 route、链接参数及深链仍能到达对应功能 |
| 把发帖操作从导航目的地移到 FAB | 发帖资格、草稿、验证、发布反馈与原站协议 |
| 私信与通知入口汇聚到消息根 | 两套现有来源、分页、未读状态及账号隔离 |
| 重排设置分类、移走玻璃效果选项 | 旧设置值及备份可读取，不删除用户原始数据 |
| 改变正文宽度、字阶与操作栏 | 阅读内容、楼层、回复树、链接和阅读位置可恢复 |
| 用标准 MD3 表面替代玻璃 | 不修改源站 DOM、认证、验证、奖励或付费协议 |

不得为入口汇聚新建一套消息数据库，不得通过重写解析器来配合视觉稿。
未在本方案提出的新服务、新订阅、新自动任务，不属于实施范围。

## 4. 公共层依赖与所有权

依赖方向固定为：业务 Route/状态适配 → 页面组合 → patterns/components → theme/纯工具。
基础 `components`、`theme` 不依赖 Session、ViewModel、NavController、repository 或网络。
跨页模式可以组合基础组件；业务数据的读取、权限判断和提交由 Route/现有状态层提供。

| 层 | 应当持有 | 不应持有 |
| --- | --- | --- |
| theme | 完整颜色角色、字阶、形状、空间/尺寸、动效角色 | 导航、账号、请求或页面级开关 |
| components | 展示值、enabled/loading、明确事件、Modifier | Session、权限查询、真实数据仓库 |
| patterns | 帖子卡、用户卡、回复条、输入组合等稳定结构 | 另一套业务状态机、通用万能 UI 配置对象 |
| screens | 页面内容排列、UI 状态展示与事件转发 | 复制公共样式、直接拼装存储迁移 |
| Route/适配 | 现有状态订阅、导航与业务回调 | 把每个状态字段变成组件里的全局依赖 |

普通二级页继续使用 `AppPageScaffold` 的 title/onBack/modifier/actions/content 五参契约。
`onBack=null` 只意味着不画返回图标；系统返回由当前导航与浮层状态处理。
聊天、帖子、源站编辑器确有不同结构时使用专用 pattern，不给普通外壳累加数十个布尔参数。
抽象应对应明确的复用场景或独立职责；单页局部排版可以留在该页，不为缩行创建任意包装。
每个 authored source 文件不得超过250个物理行；按职责拆分，不用压缩格式满足限制。

## 5. 组件实现契约

同一语义只有一个公共入口；组件默认值来自[设计系统](DESIGN_SYSTEM.md)。
视觉参数不是每个调用方都可自由覆盖的 style 对象；明确的语义变体优先于任意颜色/尺寸参数。

| 契约 | 必须满足的行为 |
| --- | --- |
| 状态提升 | checked/selected/value/loading 由调用方提供，组件只发出明确事件 |
| 异步动作 | 一次操作只提交一次；loading 与 disabled 可访问；失败保留恢复入口 |
| 开关行 | 整行一个 toggleable 语义，内部 Switch 无独立回调；点文字/控件均只切一次 |
| 列表项 | stable key；加载更多不替换已加载内容；行内独立动作不与整行点击抢占 |
| 头像 | 列表40dp、回复32dp、资料64dp；图像失败有占位，点击触区至少48dp |
| 正文 | 默认18sp/30sp、最大720dp；既有阅读字号/字体偏好仍由阅读入口解析 |
| 输入 | label 持续可见；错误靠近字段；保持焦点、选择区、草稿与键盘上下文 |
| 确认 | 说明对象与后果；取消不提交；成功/失败状态来自原业务通道 |
| Insets | 外壳传入 padding，内容消费一次；浮动操作不盖住末项或正文 |
| 无障碍 | 同一操作提供名称/角色/状态；装饰图标不重复读；模态关闭恢复焦点 |

行高采用最小值并允许文字撑高；禁止用固定 height 裁掉大字号说明或核心按钮文字。
字号因子只在主题或阅读样式入口应用一次，系统 sp 缩放继续交给 Compose。
半透明效果不应通过给整个 ColorScheme 统一设置 alpha 实现。

## 6. 主题与旧外观偏好迁移

新默认界面使用标准 MD3 色调表面，不渲染玻璃折射、色散或玻璃底栏。
静态浅色 primary 为 `#485D92`，深色为 `#B1C5FF`；其余角色以设计系统完整色表为准。
这些 primary 不是要求直接覆盖每个控件；配套 on/container/surface 角色必须同时生成或指定。
背景图仍是可选能力；表单、正文及关键操作使用不透明保护面，保证阅读与对比。

| 旧数据 | 新版读取与呈现规则 | 禁止的捷径 |
| --- | --- | --- |
| theme_mode、dynamic_color、theme_color | 延续原值的含义；新安装使用新默认方案 | 升级时删除所有主题偏好 |
| theme_style、theme_contrast、oled_dark | 继续解析，经过统一主题入口作用于配套角色 | 各页单独猜测深浅色或叠加主题 |
| 字体文件、font_key、font_scale、字重 | 保留文件/取值；将字体能力统一映射到字阶 | 替换或移除用户字体文件 |
| 背景图、背景色、透明度 | 原数据保留；展示采用新的保护面与可读性策略 | 全页面透明、只测未合成颜色 |
| keep_background_color | 键缺失采用新默认 false（带轻微色调的表面）；已保存 true 保持中性面策略、已保存 false 保持色调面策略 | 只改界面默认而忘记修改 loader/reset 的旧 true 默认 |
| tablet_mode | 键缺失采用“跟随窗口”；已保存 true 映射“跟随窗口”，已保存 false 映射“始终单内容栏”；主导航仍随窗口适配 | 直接用旧 getter 默认 false 阻止所有新用户的自适应 |
| 玻璃相关开关、bottom_bar_style | 可退为兼容数据；新版 UI 不再渲染旧效果 | 升级时改写成“用户主动关闭”或删除键 |
| 旧主题预设或未知值 | 认识的值兼容；未知值安全回退并保留原始值 | 崩溃、写回默认覆盖未知值 |

迁移后的“新默认”和“用户已保存选择”必须区分；不能每次启动以新默认覆盖用户选择。
若不再支持某个旧视觉效果，设置说明写明新版表现；不展示点了也无效的开关。
备份导入仍接收旧字段，导出仍保留兼容数据；升级并不等于重置。

“键缺失”必须通过实际存储的 contains 判断，不是拿 getter 的默认值当已保存值。读取、会话初值、分类重置和恢复默认须使用同一套新版默认策略；显式选择“始终单栏”的用户不强制双栏，但仍可使用 rail。布局设置显示“跟随窗口 / 始终单内容栏”，替代旧“平板模式”措辞；暂不需要另建具有三种状态的持久化枚举。

## 7. 根导航与旧路由迁移

UI 显示名称不作为 route key，也不作为持久化主键；沿用稳定 ID 及旧参数解析。

| 旧入口或 ID | 新呈现 | 兼容要求 |
| --- | --- | --- |
| home | 社区根 | 旧 home 深链和首页重选语义保留 |
| topicCollections / topicCollectionsRoot | 淘帖根 | 同一目的地的旧别名仍正确选中 |
| directMessages / directMessagesRoot | 消息根的私信分区 | 旧链接进入私信，不因改名跳到通知 |
| notifications 对应旧路由 | 消息根的通知分区 | 旧入口可以定位通知分区，保留原列表状态 |
| me | 我的根 | 账号/设置入口可达；游客门禁沿用 |
| forums | 社区中的板块浏览，或用户自定义根入口 | 不丢失自定义可达性，也不创建第二份板块数据 |
| newTopic | 上下文发帖 FAB | 旧路由仍可导航；新视觉不把动作当根 tab |

自定义底栏列表先保留原始顺序/值，再派生新版可见目的地；不把新默认四项强行覆盖旧自定义。
识别旧别名后按语义去重，保留首个顺序；未知 ID 保留原始数据但不渲染为无效按钮。
旧 newTopic 仍保存，显示层改为 FAB；若可见目的地集合无效，安全展示默认四项而不覆盖原值。
可见目的地 3—5 项使用标准 bar/rail；恰为两项时所有窗口使用顶部 PrimaryTabRow，消息等内部两分区改为分段控件。新导航配置支持有效的 2—5 个目的地；不足两项时派生默认四项，并通过升级说明解释发帖动作迁移及布局配置入口，不写回默认值。
储存迁移必须具备版本与幂等条件；写入前记录旧值，迁移中断后可再次执行且不反复重排。
私信和通知保留各自未读定义，不能未经确认把两套计数相加；UI 汇聚不改写业务统计口径。

## 8. 窗口变化与返回栈

默认 <600dp 使用底栏，一般 ≥600dp 使用 rail；compact 高度和特殊折叠姿态按页面规格回退。
先扣除实际导航宽度、左右系统安全区与两侧页面边距得到可用宽度 U；只有 U≥280+24+400dp，且高度≥480dp、字体布局能容纳时才双栏。两项顶部 Tab 兼容布局没有 rail 宽度占用，需扣除顶部 Tab 的高度预算。
840dp 不强制切 drawer；需要更多入口时使用明确定义的次级导航。
用户选择始终单内容栏时，不进入双栏；该偏好只限制内容布局，不禁止 root 导航随窗口转换。
窗口等级依据实际窗口，不读取物理设备类型来推断；resize、分屏、折叠时重新评估。
官方依据：[窗口分级](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)、[自适应导航](https://developer.android.com/develop/ui/compose/layouts/adaptive/build-adaptive-navigation)。

| 状态 | 单栏与双栏之间必须如何保留 |
| --- | --- |
| 所选根目的地 | 保留稳定 ID，不因切成 rail 跳回社区 |
| 每个根的子栈 | 保留详情与根位置，避免创建另一套互不关联的浏览历史 |
| 所选详情 | 保存 topicId/userId/conversationId 等业务标识，不保存组件实例 |
| 列表 | stable key、筛选、分页、可见位置保留 |
| 输入 | 草稿、引用对象、编辑选择区和提交状态保留 |
| 短暂 UI | 搜索/目录/菜单按是否仍有效恢复，不自动重放提交动作 |

返回优先级为：键盘 → 当前浮层/搜索 → 当前详情层 → 所属根；根级退出仍沿用既有产品约定。
“无返回图标”不允许吃掉系统返回；双栏关闭详情不应意外清空列表或退出应用。
点击未选中根仅切换；当前社区根的重选刷新行为与现有协调器一致，不额外发出两次请求。

## 9. 阅读位置与草稿恢复

新视觉改变行高与宽度后，旧像素 offset 不再天然对应相同文字位置。
读取 `TopicReadingPositionRepository` 的旧 floor/listIndex/scrollOffset，不清空 `lsb_reading_positions`。
新会话优先用帖子/楼层及可定位内容锚点恢复；位置缺失时使用可解释的旧值回退。
旧布局只提供粗略位置时定位到对应楼层起点，不能宣称已精确恢复到原行。
同一新版布局中的返回应保留准确可见锚点；图片异步加载后不能反复把用户拽回旧 offset。
当前 `ReadingPositionStore` 使用严格四段 CSV：floor、listIndex、scrollOffset、保存时间，TTL 为两小时；旧版遇到非四段值会删除该条。不得直接向原字符串追加字段，也不得因改版延长或重置旧记录的 TTL。
同次会话优先通过 saveable UI 状态保存细锚点；确需跨重启增加细锚点时，可在同一 preferences 用独立可选键（如 v2:<topicId>）保存带版本的元数据，不改变原数字 topicId 键及四段值。新键不得被当作旧记录 ID 读取；旧版忽略它，原 clear 仍能清理全部位置。新元数据仅在对应旧记录存在且仍有效时使用，缺失/过期/格式不识别时回退楼层；旧备份没有新键仍能读取。该扩展实施前需验证新旧版本双向读取和备份，而非仅凭本条宣称兼容。
草稿依旧通过既有生命周期保存；改变 tab 或单双栏不得清空，取消编辑与丢弃草稿需区分。
重建界面不得自动重发发布、投票、打赏、抽卡或其他有副作用的请求。

## 10. Insets、IME 与源站边界

每一种 inset 指定一个拥有者：Activity 提供 edge-to-edge，外壳/导航负责其区域，内容消费传入 padding。
嵌套 Scaffold 只将已经由父层消费的边置零；不能全局清零来掩盖重叠问题。
输入条始终位于键盘上方；列表末项、Snackbar、FAB 与操作栏不能相互遮挡。
不要手工把完整 IME 高度与系统导航栏高度相加；通过 inset 消费机制协调。
官方依据：[Compose Insets](https://developer.android.com/develop/ui/compose/system/insets-ui)。

原站 WebView 的加载、错误、关闭、在浏览器打开等应用侧外壳可改版。
Cookies、登录状态、DoH、验证回调、上传与发布桥接继续使用原通道。
不得注入全站重排 CSS/DOM 来模拟新原生页面，也不得以外观改动移除原站必要控件。
